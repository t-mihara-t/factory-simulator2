# 0.3 — 営業・設計・調達をつなぐ

## デモで試す

[デモを開く](https://factory-simulator2.tomonobumihara.chatgpt.site)。ゲーム画面の「生産管理」で着工予約とガントを確認し、「資材置場」で車種別に先行手配できます。「設定 → シナリオ選択」で追加の3シナリオへ進めます。

## 新しい物流

1. 受注は営業窓口に届きます。未着工分の予約時刻・仕掛上限・設計の空きがそろうと、受注伝票を設計へ運びます。
2. 設計完了時に設計設備を解放し、材料を手配します。材料費を支払えない案件は購入資金待ちになります。
3. 先行手配がなければ、材料費を支払い、車種別のリードタイムを待ちます。
4. 入荷した材料は資材置場から加工工場へ出発します。選択した加工工場の人員・故障・待ち枠も反映します。
5. 加工 → 組立 → 検査 → 完成品倉庫。納期までは有料保管し、納期に出荷・入金します。遅れて完成した分は即出荷と遅延控除になります。

材料は車種ごとに1両分のキットとして管理。先行在庫には購入時の材料費と、入荷から出庫まで **0.18G / 両分・ゲーム秒** がかかります。先行手配は入荷待ちを含め12両分まで。設計が終わると同じ車種の先行手配を優先的に引き当てます。まだ入荷前でも元の到着時刻を保持するため、残りの待ち時間だけで済みます。材料費を二重に請求しません。

## 生産管理と表示

- 着工予約は未着工分に適用。ガントに「着工○秒後」の開始線を表示します。秒あたりの表示幅を固定し、予測期間が伸びても同じ秒数の移動幅を保ちます。
- 全両着工済みの受注は予約変更を無効にし、すでに進行している作業を巻き戻しません。部分着工の場合は残りの車両だけを延期します。
- 人員・経路・着工予約に加えて、材料調達・先行在庫・入荷予定・購入資金待ちを予測に反映。操業と同じ処理を使うため、材料到着後の工程待ちも含みます。
- 設計前は受注伝票、加工前は素材台車、加工後は台車・部品、組立後は車体を表示。右上に対象車種の小さなアイコンを付けます。
- 設計者の製図、加工機の操作、組立工具、検査記録の2姿勢を繰り返し表示。縮小時でも作業者が見えるよう最低表示サイズを確保。停止・故障・保全時は動かさず、動きを減らす設定にも従います。
- 完成品倉庫は3アイコンまで。4両以上はアイコン列の右上に**総保管数量**を表示し、隠れた分もすべて課金・出荷対象にします。
- シナリオ達成で「Perfect Schedule」、資金切れで「Game Over」の専用画像がポップに登場します。
- スマホの縦・横で工場と管理画面の領域を分ける配置、情報の折りたたみ、上部の運転資金・出荷量のみの表示を継続します。

## 保存・会計

保存形式3。形式1・2から現金と材料の簿価を引き継ぎます。旧形式で既に着工していた車両の材料は購入済みとして扱い、設計後に再請求しません。新規着工分から新しい調達ルールになります。途中保存は端末のブラウザ内に残り、別端末には同期されません。

現金 = 初期資金 + 出荷売上 + 助成 − 材料購入 − 営業費用 − 設備投資。材料在庫には入荷待ち・資材・仕掛・完成品を含め、出荷時にのみ売上原価へ移します。受注画面に未払いの材料必要額を表示し、購入が後払いになったことによる資金の見誤りを減らします。

自動操作は、未払い材料費と2,500Gの余裕を残して受注し、故障を修理します。入門は章ごとに倉庫・用地・工場へ投資。資材シナリオでは4両分を先行手配、設計シナリオでは設計室を増設、時刻表シナリオでは初期受注を180・215・250秒後に予約します。この結果は達成可能性の確認であり、初見のクリア時間や楽しさの測定ではありません。

ブラウザ操作、モバイル実機、音声、フレームレートの確認は今回実施していません。ガントは最適化ではなく現在条件の予測で、将来の新規受注・ランダムイベント・プレイヤーの修理操作は含みません。
